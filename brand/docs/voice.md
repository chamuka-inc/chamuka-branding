# Voice

Chamuka speaks to business teams. The feel is playful, warm, and African-rooted — not toy-like, not startup-cute, not corporate-sterile.

## Principles

1. **Plain first.** Say what the thing is in one sentence. The first line of a README should be able to replace the GitHub description without a rewrite.
2. **Warm, not loud.** Humour is dry. No trailing exclamation marks, no emoji in org listings, no “best”, no marketing puff.
3. **Adult play.** Play the product can be more playful in its own UI; Play the listing stays adult. Coral is the accent, not a license to shout.
4. **Named, not nicknamed.** Surfaces say Chamuka. Do not drop “Chamuka” from a product lockup. Private nicknames stay private.
5. **Placeholders until confirmed.** Do not invent social handles. `name@chamuka.ai` is a stand-in for a person’s address.

## Repo names and descriptions

- Organisational owner: `chamuka-inc`.
- User-facing products: `chamuka-<name>` in lowercase kebab-case (`chamuka-drawit`). No camelCase in the repo name.
- Shared libraries: `@chamuka/<package>` on the registry, `chamuka-<package>` on GitHub.
- Descriptions: one sentence, what it is, no trailing `!`, no emoji.

Visual do / don’t examples: [`templates/github-repo-naming.svg`](../../templates/github-repo-naming.svg).

## UI copy

- Buttons are verbs: *Save*, *Send invite*, *Create form* — not *Submit* unless the legal meaning is submit.
- Empty states explain the next step, not the absence.
- Errors name the problem and a way forward. Do not blame the person.
- Loading copy is quiet (*Loading forms…*) — no jokes that stall a retry.
- Help text is optional and short. If it restates the label, delete it.

## Words we avoid in chrome

“Simply”, “just”, “awesome”, “unlock”, “magic”, “natively AI”. Prefer the concrete: *Draw together. Shape a form. Run a session.*
